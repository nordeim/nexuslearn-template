# AGENTS.md — NexusLearn

Compact instruction file for AI coding agents working in this repository. Every line answers: *"would an agent likely miss this without help?"*

## What this is

NexusLearn — an e-learning platform (marketing site + course catalog + enrollment + progress-tracking dashboard + AI study assistant), cloned pixel-faithfully from a reference app. **Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4 + Prisma/SQLite + shadcn/ui-style components.** Single app, no monorepo.

## Commands (bun is the runtime — `bun.lock` is authoritative)

|---|---|

| DB schema push | `bun run db:push` |

## Critical gotchas (these WILL bite you)

1. **Tailwind v4 is CSS-first.** There is **no `tailwind.config.js`** — all tokens live in `src/app/globals.css` under `@theme` / `@theme inline` (`docs/Tailwind-V4-Validation-Report.md`). Do not create one.
2. **Theme color vars must be FULL color values** — `--background: hsl(0 0% 100%)`, never the v3-style bare triplet `0 0% 100%`. Bare triplets silently resolve to *transparent* under `@theme inline`. This exact bug was found and fixed during the build.
3. **The v3-era palette is pinned in `@theme`** (gray/slate/cyan/purple/pink/...). Do not remove — Tailwind v4's default oklch palette drifts 1–3 sRGB units per channel from the reference app's colors and breaks the computed-style parity tests.
4. **Prisma SQLite paths are resolved by `prisma/db-url.ts`** — the Prisma CLI resolves `file:` URLs against `prisma/schema.prisma`, the runtime against process CWD (and the standalone server `chdir()`s into `.next/standalone/`, which contains its own traced copy of `prisma/schema.prisma`). Never construct a PrismaClient without `datasourceUrl: resolveDatabaseUrl()` (see `src/lib/db.ts` and `prisma/seed.ts`). `DATABASE_URL="file:../db/custom.db"` resolves to `<repo>/db/custom.db` for CLI, dev, seed, standalone and e2e alike.
5. **`datasources: { db: { url } }` is ignored by Prisma 6** — use `datasourceUrl` instead.
6. **Route casing is intentional**: `/Courses`, `/AIAssistant`, `/CourseDetail?id=…`, `/BecomeInstructor`, `/Pricing`, `/About`, `/Contact`, `/Dashboard`, `/login` — they mirror the original app 1:1. `/` is the landing page; `/Home` renders the landing directly (the reference footer links there — no redirect) **with the identical hero-state navbar** (session 10: the Navbar's `overHero` covers BOTH `/` and `/Home` — transparent + white logo at scroll 0, white-nav after scroll).
7. **Every non-landing page uses the reference shell**: root `min-h-dvh` > `main.pt-20` > `div.min-h-screen.bg-gray-50` wrapping the dark hero + content. Without `main.pt-20` the hero slides under the fixed navbar (the h1 renders at y=64 behind the 81px bar) — pinned by the session-4 e2e shell specs.
8. **The mobile menu is the highest-regression-risk chrome** (Tailwind v4 display-mismatch bugs). Rules: trigger + panel use symmetric `md:hidden`; desktop row `hidden md:flex`; page roots use `min-h-dvh`; body scroll lock while open; real `<button>` with `aria-expanded`/`aria-controls`. The trigger carries the BARE reference classes (`md:hidden p-2 rounded-lg text-white/80` over the hero, `text-gray-700` otherwise — no hover/transition utilities); the ARIA wiring is deliberate clone-only a11y hardening. `tests/e2e/mobile-navigation.spec.ts` pins all of this — run it after any nav change.
9. **Auth is first-party**: HMAC-SHA256 signed cookie (`nexus_session`) + scrypt password hashing, in `src/lib/session.ts` (pure, testable) and `src/lib/auth.ts` (Next `cookies()` adapter). **Reference parity behaviors**: signing in returns to `/` (not `/Dashboard`), and `/Dashboard` renders for signed-out visitors (generic "Welcome back", zeroed stats, empty state — no server redirect). There is no auth provider dependency.
10. **`z-ai-web-dev-sdk` is server-only** — it must never be imported into client components. The AI chat goes through `POST /api/ai/chat`.
11. **Images are remote Unsplash URLs** — allowlisted in `next.config.ts` `remotePatterns`. Cards intentionally use plain `<img>` (matching the reference markup), so `@next/next/no-img-element` is disabled in `eslint.config.mjs`. The reference's Python-course image URL is corrupt (0×0 load); the clone ships a working Python image on purpose.
12. **`Course.longDescription` is nullable on purpose** — the reference app populates the expandable "About This Course" section for only 4 of the 9 courses; absent means the section (and the left column's `space-y-12`) is not rendered.
13. **The login card is a 5-view state machine that owns the WHOLE card interior** (signin → reset → reset-sent → signup → verify). The chrome — logo ring + glow, the "Welcome to NexusLearn" h1 + subtitle, the Google button, the OR divider — renders ONLY on the signin branch of `LoginForm.tsx` (session 11); every other view replaces the entire card body with its own content wrapped in `div.w-full > div.space-y-4…` (NO logo/h1/Google/OR — the live app swaps the whole interior per view). The reset email input is its own `text-base` variant (`RESET_INPUT_CLS`); the signup inputs carry `text-sm sm:text-base` (`COMPACT_INPUT_CLS`). Email delivery is SIMULATED: signup logs a 6-digit code server-side and `/api/auth/verify` accepts any complete 6-digit code (no SMTP in the template; wire real email before production). `User.emailVerified` defaults true so seeded accounts skip verification.
14. **Head metadata is reference-pinned** — ONE root description (the "SkillSphere…" sentence) everywhere, OG/Twitter cards, per-route canonicals, `/logo.png` favicon + `manifest.json`. Do not add per-page `description` overrides; `NEXT_PUBLIC_SITE_URL` feeds `metadataBase` at build time.
15. **Course-card eyebrows use the display map** (`src/lib/course-eyebrow.ts`): "Personal Development" renders as "Personal Dev" on cards while the filter + landing grid keep the full name — reference behavior.
16. **CourseDetail never 404s** — unknown/missing `?id=` renders the in-page "Course not found" state inside the gray shell (reference behavior), not `notFound()`.
17. **The newsletter form is a client island** (`NewsletterForm.tsx`) — never a native `action=` POST (that navigates the browser to the raw JSON). Same for contact: fetch + in-place success state.
18. **OG identity mirrors the document head** (session 6): `og:title` + `twitter:title` = the per-route document title and `og:url` = the per-route canonical (CourseDetail's includes `?id=`). Every route sets metadata through `routeMetadata()` (`src/lib/metadata.ts`) — a child route's `openGraph`/`twitter` objects REPLACE the root's wholesale, so the helper restates the full payload (description, images, siteName). `/` and `/login` keep the plain "NexusLearn" title (reference behavior).
19. **The CourseDetail sidebar ends with the level row** — `mt-6 pt-6 border-t` divider > Award icon (`text-amber-500`) + "`{level} Level`" — present on every course (reference behavior, session 6).
20. **The seed array IS the display order** (session 7): `prisma/seed-data.ts` lists the courses in the reference app's "Newest" order (WebDev, DataScience, Cloud, Business, EmotionalIQ, ML, UI/UX, AdvancedPython, DigitalMarketing); the ids `seed-1…9` + `sortOrder` follow the array index, so the catalog's id-based "newest" sort and the landing featured grid (the featured subsequence) both reproduce the reference order. Do not re-sort the array.
21. **Category icons render near-black on purpose** (session 7): the reference ships `bg-gradient-to-r from-X-500 to-X-600 bg-clip-text` on the category svgs — the gradient is visually DEAD (background-clip:text on an SVG clips the gradient away; the strokes render in the inherited near-black). The clone copies those classes verbatim; the only visible color comes from the `bg-X-500/10` tint wrappers. Do not replace them with `text-X-600` colors.
22. **The level badge is a plain DIV with emerald Beginner** (session 7): live renders `inline-flex items-center rounded-md px-2.5 py-0.5 … hover:bg-primary/80 absolute top-3 left-3 bg-emerald-100 text-emerald-700 border-0 font-medium text-xs` (Beginner=emerald, Intermediate=amber, Advanced=red) — not the shadcn Badge span, and the class order is pinned.
23. **`SelectTrigger` ships the v3-era shadcn string** (session 7): `flex h-9 items-center justify-between whitespace-nowrap border bg-transparent px-3 py-2 text-sm shadow-sm ring-offset-background … [&>span]:line-clamp-1` + `h-4 w-4` chevron — the reference app predates the new-york v4 trigger (`data-[slot=select-value]`, `shadow-xs`, `ring-[3px]`). Call-sites add `w-[150px|160px|180px] rounded-xl border-gray-200` (Courses) / `w-full border-input mt-2 rounded-xl` (Contact).
24. **The seed must CLEAR optional fields, not just set them** (session 8): Prisma's `update` only touches keys present in the payload — `prisma/seed.ts` restates `longDescription: c.longDescription ?? null` so a re-seed over an existing DB nulls removed values. Without it, the session-7 reorder left the pre-reorder texts on seed-3/4/5 (phantom "About This Course" sections the live app does not render). Pinned by the session-8 About-presence e2e matrix.
25. **The "What You'll Learn" check list is tags ONLY** (session 8): the live list renders exactly the parsed tags — no `{level} Level` row inside `div.space-y-3` (the old `whatYouLearnTopics()` helper was removed). The level renders ONCE, in the Award-icon divider row (`div.mt-6.pt-6.border-t`). Pinned by the session-8 e2e specs.
26. **Dashboard stat icons are lucide components** (session 8): `BookOpen`/`CirclePlay`/`Award`/`TrendingUp` (`className="h-5 w-5"`) — the reference ships the `lucide lucide-X` classes + `width="24" height="24"` attributes; do not replace them with hand-inlined svgs. The stats grid is the BARE reference grid (no hook classes), and both MyCourses empty-state buttons carry the shadcn base trio.
27. **Tailwind v4 rewrote the `space-y-*`/`space-x-*` engine — direct margin utilities on children now WIN** (session 9): v3 shipped `.space-y-1 > :not([hidden]) ~ :not([hidden]) { margin-top }` (specificity 0,2,0 — it OVERRIDES a child's `.mt-3`), while v4 ships `:where(.space-y-1 > :not(:last-child)) { margin-block-end }` (`:where()` = zero specificity — the child's `.mt-3` WINS, and the margin moved to margin-bottom-of-non-last). Any `space-y-*` container whose child carries an explicit `mt-*`/`mb-*` utility renders different gaps on v4 than the v3 reference despite byte-identical classes. The one case in this app: the mobile nav panel CTA — the reference ships `block mt-3` but renders a 4px gap (v3 wins); the clone ships `block` (dropping the dead-under-v3 `mt-3`) to render the reference 405px panel. The Navbar's two "My Dashboard" buttons also now carry the shadcn base trio + `hover:bg-primary/90` (the reference's navbar received the same button-base sweep as the landing in session 7 — the navbar lives outside `<main>`, so `main *`-scoped class audits never covered it; audit the chrome subtree separately).
28. **The Navbar lives outside `<main>`** (session 9): it renders in the root layout, so a `main *`-scoped class-set diff will NEVER catch navbar drift. When auditing chrome parity, diff the `nav *` + `footer *` subtrees separately (the session-9 audit found the navbar buttons + trigger + the space-y trap exactly this way).
29. **Text content needs its own audit surface — height and class sweeps cannot see copy or glyphs** (session 11): a one-line description swap wraps to the same card height, and U+201C vs U+0022 renders at identical metrics, so the landing's path-card copy drift and the testimonial curly-quote drift survived ten audits. The standing surfaces: a normalized `innerText` diff (collapse whitespace → split lines → SequenceMatcher) over `main` per route, plus PER-VIEW state diffs for stateful components (the login card's 5 views — a default-state-only diff missed that the live app replaces the whole card interior per view). Pinned by the session-11 specs.
30. **Tailwind v4 SHIFTED the shadow scale — `shadow-sm` renders one notch heavier than the v3 reference** (session 12, the FIFTH v4 trap): v4 renamed v3's `shadow-sm` (`0 1px 2px rgb(0 0 0/0.05)`) to `shadow-xs` and moved `shadow-sm` up to v3's bare-`shadow` geometry (`0 1px 3px/0.1 + 0 1px 2px -1px/0.1`). Byte-identical classes, different token value — class diffs are structurally blind to it. The fix is the `--shadow-sm` token pin in `globals.css` `@theme inline` (the ADR-005 palette-pin precedent: pin the token, keep every class byte-identical — one line fixes all 21 usages + every `hover:shadow-sm`). md/lg/xl/2xl are UNCHANGED in v4 (GUARD specs pin them). Pinned by the session-12 specs, which assert the COMPUTED box-shadows (normalized by stripping v4's empty zero-alpha composition slots).
31. **Hover-state audits need a hover-capable context and per-stack property reads** (session 12): v4 wraps every `hover:` variant in `@media (hover: hover)` (v3 emitted them unconditionally) — a headless browser launched with touch emulation (e.g. the agent-browser daemon: `matchMedia("(hover: hover)")` is false there) matches `:hover` but never applies the hover rules, producing FALSE parity failures; the repo's Playwright Chromium reports `hover: hover` true and is the correct probe context. Also: v4 renders `translate-y-*`/`scale-*`/`rotate-*` through the standalone CSS properties (`translate`, `scale`, `rotate`) while v3 uses `transform: matrix(...)` — a computed-style assertion reading `.transform` on the clone reports "none"; read both properties per stack. Real-world consequence (documented variance, an improvement): on touch devices v4 kills v3's sticky-hover-on-tap.
32. **The dev server must be opened via `localhost:3000` — or `127.0.0.1` must be allowlisted** (session 12): Next 16's dev-origin protection blocks the dev CSS/JS chunks when the Origin/Referer host (`127.0.0.1`) differs from the server's own (`localhost`) — the page silently renders UNHYDRATED (forms fall back to native GET submits, e.g. `/login?`). The production build is unaffected. `next.config.ts` now carries `allowedDevOrigins: ["127.0.0.1"]` so both origins hydrate.
33. **Cascade-ORDER variances are invisible to class diffs — the runtime-cascade pin** (session 13): the reference app (Tailwind v3 + the Base44 runtime) injects a page-level utility `<style>` sheet AFTER its static build; on `/login` that runtime sheet re-asserts `.focus:ring-slate-400:focus` at a later cascade position, which wins `--tw-ring-color` over the static `.focus-visible:ring-ring:focus-visible` whenever BOTH pseudos match (keyboard focus) — the reference's login inputs render a SLATE-400 focus ring, not the `--ring` near-black. The clone's single compiled v4 sheet emits the focus-visible variant later, so the winner flipped. Same blind-spot family as the shadow-scale shift (token VALUES) and DOM nesting: the class string is byte-identical in all three. The fix is the UNLAYERED rule in `globals.css` (`.focus\:ring-slate-400:focus { --tw-ring-color: var(--color-slate-400); }` — unlayered beats every `@layer` rule in the cascade); the pin's selector matches ONLY the login inputs' class strings (the three CLS constants in `LoginForm.tsx` are the only `focus:ring-slate-400` usages). Pinned by the session-13 specs incl. GUARD specs proving /Contact + the buttons keep the `--ring` ring.
34. **Focus-state audits need site-CSS reads and post-transition timing** (session 13): (a) the UA-default `outline: auto` computes DYNAMIC values (contrast-adaptive colors, animation-dependent widths/alphas — 1px/2px/3px, `rgba(10,10,10,0.5)`…) that differ run-to-run; never probe it for parity — read the site-CSS-controlled properties (`--tw-ring-color`, explicit outlines) instead; (b) elements carrying `transition-all` (every shadcn button) render their focus ring MID-TRANSITION on an immediate computed read (the ring slots read zero-alpha) — wait ≥ 2× the transition duration before reading; (c) v4's ring composition prefixes every box-shadow with empty zero-alpha slots — full-string reads or slot filtering required (truncation hides the ring). Also: the reference's runtime ships a UNIVERSAL `* { scroll-behavior: smooth }` — the clone pins the same universal rule in `@layer base` (not just `html`), which also smooths programmatic scrolls inside inner scrollers (Radix SelectContent keyboard nav).
35. **The reference ships NO webfont — match the DECLARED stack, never bundle the named font** (session 14): the reference (Base44 + v3) declares `body { font-family: Inter, system-ui, -apple-system, sans-serif }` via a runtime-injected inline sheet on 9 of 10 routes but loads NO @font-face anywhere (`document.fonts` is empty on every route) — every visitor renders their SYSTEM font (or a locally-installed Inter). The clone's previous next/font bundle rendered real Inter glyphs the reference never shows — the root cause of the 13-session "font-metric height bands" (every documented height delta was a font-metric artifact). After replacing the bundle with the `--font-sans` token in `@theme`, EVERY height measurement in the project is byte-exact: 11 routes × 2 viewports + all 9 CourseDetail pages. Audit rule: probe `document.fonts` + the computed stack + a measured probe-string width — a font-family STRING match means nothing if one side loads the webfont and the other falls through.
36. **v4 dropped the v3 button-cursor preflight** (session 14 — the sixth v4 trap): v3's preflight shipped `button, [role="button"] { cursor: pointer }`; v4 removed it (buttons revert to the UA-default arrow). Measured: 42 default-cursor elements on the clone's landing vs ZERO on the reference (whose static AND runtime sheets both carry the rule). The restored `@layer base` rule keeps any element-level `cursor-*` utility winning (utilities > base). GUARD specs pin the labels default + the inputs text so the rule can never over-apply. A preflight delta is the FOURTH structural-blind-spot class with byte-identical classes (after token values, DOM nesting and cascade order).
37. **v3↔v4 line-height composition flips on `text-*` + `leading-*` combos** (session 14 — the seventh v4 trap): v3 emits responsive `text-*` rules inside media blocks AFTER every base utility, so `md:text-7xl`'s OWN `line-height` beats a plain `leading-tight` (the reference's hero H1 lh = 1, hero P = 1.75rem, CTA H2 = 1); v4's `--tw-leading` custom-property composition makes `leading-*` win regardless of order (1.25/1.625 — the clone rendered 90px line boxes vs the reference's 72px). Four UNLAYERED media-scoped pins restore the reference winners (`.sm:text-5xl.leading-tight`, `.md:text-5xl.leading-tight`, `.md:text-7xl.leading-tight` → 1; `.md:text-xl.leading-relaxed` → 1.75rem). Below the variant breakpoints both engines agree — the drift only exists where the responsive size activates.
38. **v4's `:where()` space-y engine loses gaps on INLINE children and on children carrying their own margin utilities** (sessions 9 + 14 — traps three, eight and ten in the engine family): v4 assigns the gap to NON-LAST children as `margin-block-end`; v3 assigned it to FOLLOWERS as `margin-top`. Two failure modes: (a) the gap carrier is INLINE (the login form's `<label>`s — vertical margins are inert on inline boxes) — the whole 6px gap vanishes (each field group 6px short, the mobile /login page −12px); (b) the gap carrier carries its OWN margin utility, which beats the `:where()` zero-specificity rule (the login card's `-mb-2` back-button replaced the 16/24px header gap with −8px, pulling the view heading up into the button). Two scoped follower-margin pins in `globals.css` restore the reference gaps; the mobile panel CTA (session 9) keeps its engine-variance form by design. Desktop /login heights never showed either case (the h-screen viewport clamp) — found by the per-view sibling-gap audit.
39. **The reference's scroll-reveal system kills transform utilities — replicate the RESTING state** (session 14 — the ninth v4 trap + a session-13 record correction): the Base44 runtime pre-hides offscreen sections with INLINE `opacity: 0; transform: translateY(20px)` (35 elements on /) and, once revealed, leaves INLINE `opacity: 1; transform: none` FOREVER — inline styles beat every stylesheet rule, so the popular pricing card's `scale-105` is permanently DEAD on the reference (both cards render unscaled, 498px). The clone (no reveal system) applied v4's standalone `scale: 1.05` — 5% larger than the reference. The unlayered `.scale-105 { scale: none }` pin replicates the resting state; `hover:`/`group-hover:` scale variants are different class names and stay live (GUARD-pinned). CORRECTION of the session-13 record: the reveal system DOES exist and fires on scroll (the "zero offscreen-hidden elements" probe read the wrong property — it must look for INLINE `opacity: 0` styles, and it now does); the reveal ENTRY animation itself stays a documented variance (the end states match). Also: Tailwind v4's automatic source detection scans EVERY non-gitignored file — the repo's skills/, docs/ and tests/ folders (agent documentation + specs that QUOTE utility names) leaked 1027 unused rules into the compiled CSS (51%); the `@source not` directives in `globals.css` restrict generation to app source, canary-pinned by the leak spec.

- `skills/` — reference skill library (excluded from tsconfig/eslint; not app code)

## Conventions

- Style: Tailwind utility classes copied verbatim from the reference app; design tokens documented in the PAD §5 (Design System Reference) and `src/app/globals.css`.
- Components: function declarations (not arrow exports), `data-slot` attributes on primitives, `cn()` for class merging, CVA for button/badge variants.
- No raw SQL; all data access through Prisma. All route handlers validate input and return `{ error }` JSON with proper status codes.
- Computed-style parity with the reference app is a regression gate — if you change shared components (buttons, cards, nav), re-verify colors/radii/typography match the values recorded in `docs/screenshots/` and the PAD.
